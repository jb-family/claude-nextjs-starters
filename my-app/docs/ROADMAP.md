# StarterKit 개발 로드맵

이 로드맵은 PRD에 정의된 기능 요구사항을 기반으로 작성되었다.
현재 버전은 UI 템플릿(목업 데이터)만 구현된 상태이며, 실제 서비스로 전환하기 위한 단계를 아래와 같이 정의한다.

---

## 현재 상태 (v0.1 - 완료)

UI 프레임워크, 레이아웃, 컴포넌트 예제가 구현된 기반 템플릿.
모든 데이터는 하드코딩된 목업이며 실제 백엔드 연동 없음.

**완료된 기능:**
- F001 랜딩 페이지 (Hero/Features/CTA)
- F002 대시보드 (목업 통계 카드 + 활동 테이블)
- F003 컴포넌트 예제 갤러리 (6종)
- F004 문서 페이지
- F005 반응형 사이드바
- F006 다크/라이트 테마 전환
- F010 로그인 폼 UI
- F011 회원가입 폼 UI
- F020~F025 컴포넌트 예제 6종

---

## Phase 1: 인증 실제 연동 (v0.2)

**목표**: UI 목업 상태의 인증을 실제 동작하는 인증 시스템으로 교체한다.

**예상 기간**: 1~2주

### 작업 항목

| 작업 | 설명 | 관련 기능 |
|------|------|----------|
| Supabase 프로젝트 설정 | Supabase 계정 생성, 프로젝트 초기화, 환경변수(.env.local) 구성 | F010, F011 |
| Supabase Auth 로그인 연동 | `supabase.auth.signInWithPassword()` 호출로 실제 JWT 토큰 발급 | F010 |
| Supabase Auth 회원가입 연동 | `supabase.auth.signUp()` 호출, 이메일 확인 플로우 처리 | F011 |
| 로그아웃 기능 구현 | `supabase.auth.signOut()`, 세션 클리어 후 랜딩 페이지 리디렉션 | F010 |
| 보호된 라우트 미들웨어 | `middleware.ts`에서 세션 없는 `/dashboard` 접근 시 `/login`으로 리디렉션 | F002 |
| 인증 상태 헤더 UI 반영 | 로그인 상태에 따라 헤더에 로그인/로그아웃 버튼 전환 표시 | F006 |

### 마일스톤

- 회원가입 → 이메일 확인 → 로그인 → 대시보드 전체 플로우 동작 확인
- 비로그인 상태에서 `/dashboard` 직접 접근 시 `/login`으로 리디렉션 확인

---

## Phase 2: 핵심 기능 실제 데이터 연동 (v0.3)

**목표**: 대시보드 및 사용자 관련 기능을 실제 데이터베이스와 연결하여 실용적인 관리 화면으로 전환한다.

**예상 기간**: 2~3주

### 작업 항목

| 작업 | 설명 | 관련 기능 |
|------|------|----------|
| Supabase DB 스키마 생성 | users, activities 테이블 SQL 마이그레이션 작성 및 적용 | F002 |
| 대시보드 통계 API 구현 | Next.js Route Handler에서 집계 쿼리 처리, 통계 카드 실제 데이터 표시 | F002 |
| 활동 로그 API 구현 | activities 테이블 CRUD Route Handler 구현, 대시보드 테이블 실시간 반영 | F002 |
| TanStack Query 연동 | `useQuery` 훅으로 대시보드 데이터 패칭, 로딩/에러 상태 처리 | F002 |
| 사용자 프로필 페이지 추가 | 로그인한 사용자의 이름/이메일 확인 및 수정 페이지 신규 구현 | 신규 |
| Zustand 인증 스토어 구현 | 로그인 상태, 사용자 정보를 전역 스토어로 관리 | F010, F011 |

### 마일스톤

- 대시보드 통계 카드가 DB 집계 값을 실시간으로 표시
- 활동 로그가 실제 DB에서 조회되어 테이블에 렌더링
- 사용자 프로필 조회 및 이름 수정 가능

## Phase 3: 확장 기능 (v1.0)

**목표**: 실제 SaaS 또는 어드민 도구로 활용할 수 있는 수준의 완성도를 달성한다.

**예상 기간**: 3~4주

### 작업 항목

| 작업 | 설명 | 관련 기능 |
|------|------|----------|
| 사용자 관리 페이지 | 관리자가 전체 사용자 목록 조회, 역할 변경, 계정 비활성화 처리 | 신규 |
| 소셜 로그인 연동 | Supabase Auth의 Google/GitHub OAuth 연동 | F010 |
| 이메일 인증 플로우 개선 | 회원가입 후 이메일 확인 안내 페이지, 재발송 기능 | F011 |
| 비밀번호 재설정 기능 | 이메일 기반 비밀번호 재설정 요청 및 처리 페이지 신규 구현 | 신규 |
| 페이지네이션 구현 | 활동 로그 및 사용자 목록에 커서 기반 페이지네이션 적용 | F002 |
| 국제화(i18n) 기반 구조 | next-intl 도입, 한국어/영어 전환 기본 구조 설정 | 신규 |
| Vercel 배포 자동화 | GitHub Actions CI 파이프라인 구성 (lint → build → deploy) | 신규 |
| 접근성 감사 | 키보드 탐색, 스크린 리더 호환성, WCAG 2.1 AA 기준 점검 | 전체 |

### 마일스톤

- Google 또는 GitHub 계정으로 소셜 로그인 동작 확인
- 비밀번호 재설정 이메일 발송 및 재설정 완료 플로우 확인
- Vercel 배포 후 프로덕션 URL에서 전체 플로우 동작 확인

## 기술 부채 및 개선 사항

현재 v0.1 코드에서 실제 서비스 전환 시 반드시 처리해야 하는 항목:

1. **인증 로직 실제 구현**: `login/page.tsx`와 `signup/page.tsx`의 `setTimeout` 시뮬레이션을 실제 API 호출로 교체
2. **환경변수 관리**: `.env.local.example` 파일 추가 및 필수 환경변수 문서화
3. **에러 처리 강화**: `error.tsx` 페이지를 실제 에러 유형별로 분기 처리
4. **로딩 상태**: `loading.tsx` 컴포넌트를 Skeleton UI로 교체하여 레이아웃 시프트 방지
5. **테스트 코드 부재**: Phase 2 시작 전에 핵심 유효성 검사 로직에 대한 단위 테스트 추가 권장
